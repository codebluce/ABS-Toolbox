## 4. 当前阻断问题

### P1-01 QC 失败会破坏上一版正式产物

生成器先直接写入 `out_path`，随后重新读取并执行结构 QC；异常时删除同一路径。若该路径原本已有可用正式版本，它已在 QC 前被覆盖，失败分支还会将其删除。

**影响**：发布虽然被阻断，但上一版产物可能丢失，违反首轮“失败不覆盖上一版”的验收标准。

**修复建议**：在输出目录创建临时文件，完成写入和 QC 后使用 `os.replace()` 原子替换；异常仅删除临时文件。增加“预置旧文件—注入 QC 失败—旧内容及哈希不变”的测试。

### P1-02 `--no-push` 会移动本地发布分支

当前流程在 detached worktree 中提交后，即使选择 `--no-push`，仍执行 `git update-ref refs/heads/<branch> <committed_sha>`。

**影响**：名称容易被理解为无副作用预览，但实际会创建提交并改变本地引用；自动化脚本或人工验收可能污染本地状态。

**修复建议**：明确拆分 `--build-only`、`--commit`、`--push`；build-only 不创建提交、不更新引用。若保留现有含义，应重命名并在执行前明确提示副作用。

## 5. 新发现及残余风险

### P2-01 无本地发布分支且无文件变化时发布失败

真实临时仓库演练已复现：远端存在 `gh-pages`，本地不存在同名分支，站点内容与远端一致。流程正确创建 detached worktree，发现无变化后却执行：

```text
git push origin gh-pages:gh-pages
error: src refspec gh-pages does not match any
```

**修复建议**：无变化时无需 push；比较远端 SHA 与 detached `HEAD` 后直接成功退出。确需推送时使用明确存在的 `HEAD:refs/heads/<branch>`。

### P2-02 `fallback_mtime=False` 参数无效

当所有候选文件均无可解析业务日期时，函数无条件按 mtime 返回文件，未遵守参数要求。

**修复建议**：禁用回退时抛出带候选清单的 `FileNotFoundError` 或领域异常，并补正反向测试。

### P2-03 提交消息日期可能与实际构建产物错配

构建已经确定 `latest_dashboard`，但提交消息又重新扫描目录并按 mtime 选取日期。旧文件被触碰后，提交消息可记录另一份看板日期。

**修复建议**：直接由本次传入 `build_site()` 的产物路径计算 `date_tag`，不要二次扫描。

### P2-04 `build_site()` 对相对路径不健壮

调用方传入相对看板路径时，`relative_to(REPO_ROOT)` 可抛出 `ValueError`。当前主入口通常提供绝对路径，但函数接口未声明该前置条件。

**修复建议**：入口统一 `resolve()`，并校验产物位于允许目录；错误信息应说明实际路径和允许根目录。

### P2-05 浏览器兼容与真实性能仍未验收

客户端已能区分“不支持解压”与密码错误，但仍依赖原生 `DecompressionStream`，没有兼容回退；也没有真实浏览器自动化覆盖错误密码、目标移动端及峰值内存。

**修复建议**：提供轻量 gzip 回退或兼容构建；使用目标 Chrome、Edge、Safari 做自动化解锁和性能预算测试。

## 8. 下一轮修复优先级与验收标准

### 优先级 A

1. 临时文件生成、QC 后原子替换，失败时旧产物哈希不变。
2. 将 no-push/build-only 改为无提交、无引用变更的真正预览。
3. 修复无本地分支且无变化场景，并增加真实临时 Git 仓库测试。

### 优先级 B

1. 实现 `fallback_mtime=False` 严格语义。
2. 提交消息日期复用实际构建产物。
3. 统一路径解析和边界校验。
4. 增加浏览器兼容回退和目标浏览器自动化。

### 验收标准

- QC 失败返回非零，旧正式产物内容和哈希保持不变。
- build-only/no-push 后仓库所有 refs、HEAD 和工作区均不变化。
- 无本地分支、落后、领先、分叉、无变化、push 失败均有真实 Git 集成测试。
- 构建文件、manifest 和提交消息引用同一业务日期与同一源产物。
- 禁用 mtime 回退时，无业务日期候选必须明确失败。
- 目标浏览器均可解锁；记录首屏可交互和峰值内存并设置回归预算。

## 9. 最终结论

本轮修复已解决多数显性功能缺陷，测试从 41 项提升到 62 项，发布链的远端基线和站点泄漏控制也明显增强。但“失败保护旧产物”和“发布命令副作用可控”仍未达到可靠发布标准，且真实 Git 演练发现确定性失败路径。

因此本轮结论仍为 **NEEDS_REVISION**。完成优先级 A 并通过真实 Git 集成矩阵后，可再次申请专项验收；性能拆分可在可靠性门禁完成后推进。
