# dashboards/ 目录说明

ABS发行定价与机构统计看板的归档目录（v2.0.0 英文化）。

## 目录结构

```
dashboards/
├── 01_latest/         ← 当前最新日期的看板（快速访问入口）
├── 02_history/        ← 按日期子文件夹归档的历史版本
├── 03_test/           ← 测试/调试产物
├── 04_reference/      ← md文档类参考资料
└── README.md          ← 本文件
```

## 文件命名规则

正式看板统一命名格式：`YYYYMMDD_<看板名>.html`

| 看板名 | 来源工具 | 说明 |
|--------|---------|------|
| `发行定价分析工具` | gen_abs_cost_report.py | 成本分布分析（月份/资产类型/期限） |
| `机构投标利率看板` | gen_compare_tool.py | 机构成本交互式比对 |
| `机构投标基准利差看板` | gen_spread_report.py | 基准利差分析 |
| `机构统计看板` | gen_institution_stats.py | 机构统计三表 |

示例：`20260617_发行定价分析工具.html`

## 更新流程

每次生成新看板时：

1. **归档旧最新版本**：将 `01-最新版本/` 中的4份HTML移到 `02-历史版本/<原日期>/` 子文件夹
2. **放入新看板**：新生成的4份HTML放入 `01-最新版本/`
3. **测试产物归档**：调试或测试产物放 `03-测试文件/`，不进入正式版本

## 历史版本子文件夹命名

按日期命名：`YYYYMMDD`（如 `20260603/`）

每个历史子文件夹内保留该日期的4份完整看板（如果某次只有部分看板更新，仍保留当时所有生成的版本）。

## 最新簿记面板（必选模块）

本地预览：`03_test/ABS综合看板_最新簿记Demo_20261010.html`，默认打开“发行定价 > 最新簿记”，保留原综合看板其他面板；不替换或发布正式版本。

按定稿文件名的业务日期自动选取最新台账，生成新的预览文件（输出路径必须不存在）：

```bash
.venv/bin/python scripts/latest_bookkeeping_panel.py \
  --base deliverables/dashboards/01_latest/ABS综合看板_20260924.html \
  --output deliverables/dashboards/03_test/最新簿记Demo_新版本.html
```

也可用 `--ledger <定稿台账.xlsx>` 指定来源；不传 `--base` 时生成独立面板预览。全量综合看板生成器默认包含该面板，`--bookkeeping-demo` 仅保留 Demo 标识，正常生成与发布不再需要额外开关。

口径：仅纳入发行场所为上交所、深交所及银行间的项目，先剔除非标、保登及其他场所，再按每类资产的有效簿记日期取最近3个不同簿记日期，同日项目全部保留；成本取 T 列，最终配售取 U/V 列，申购明细取 W/X/Y 列。两套明细独立展示，不按行配对、不以申购规模替代认购份额。缺失报价不回退历史项目、不虚构补全。机构原名与自持记录保留，因此和采用过滤规则的统计面板不一定同口径。

明细卡片固定按“申购明细 → 最终配售”排列，默认展示申购明细；导出口径及文件名统一使用“最终配售”。

表格固定列：申购明细为“档位 / 机构名称 / 申购利率 / 申购规模（亿元）”；最终配售为“档位 / 机构名称 / 成本利率 / 配售规模（亿元）”。CSV 与当前视图共用相同列定义，项目名称及簿记日期保留于概况卡片，项目名称也保留于导出文件名，不在明细表内重复。

资产卡片顺序：赊销白条、金条白取混发、信托金条、白条取现、信托企业主贷、小贷企业主贷、保理、金采、京企贷、动产质押、汽车融资租赁；其他类型按源表首次出现顺序排在其后。台账“金条&白取混发”显示为“金条白取混发”；“白条取现”和“信托白取”先归并为“白条取现”，再在满足发行场所规则的项目中统一选最近3个不同簿记日期，同日项目全部保留。

明细卡片标题为“簿记明细”，不展示视图下的说明小字。表格档位标签采用文字加颜色：优先A蓝、优先B青、优先C金、优先D橙、中间级/夹层紫、次级红、未分层等其他档位灰；两种明细视图保持同档位同色。

### 同步更新和校验门禁

- `gen_integrated_dashboard.py` 每次运行都重新读取原始定稿“总表”，生成最新簿记；不复用跨行填充的共享临时台账。
- `increment_merge.py` 直接输出到受控 `03_final/YYYY年ABS发行台账-MMDD-定稿.xlsx` 时，先校验临时台账，再保存；若是当前最新定稿，自动刷新已有综合看板的簿记模块。
- `abs_archive.py ledger` 晋升受控命名的定稿时也校验并刷新。加工中、历史定稿及不符合定稿命名的文件不会自动更新正式看板。
- 手工 Excel 编辑或复制文件不会触发磁盘监听；此时执行下面的同步入口。发布前（含 `--skip-generate`）会核对最新定稿哈希、当前规则指纹、实际 HTML/JS/CSS；旧面板不能绕过门禁。
- 增量刷新仅替换簿记组件，保留其他模块原有数据快照和内容；需要其他模块同步更新时运行完整生成流程并提供各自源表。
- 手机版随打包复用同一组件和数据。更新过程不自动上传台账、commit、push 或发布站点。

```bash
# 手工更新定稿后：保留综合看板其他模块，更新簿记模块
.venv/bin/python scripts/update_latest_bookkeeping.py

# 全量自检：回归测试、原始源表逐笔核对、真实 JS/CSV 全量运行时、实际产物校验
.venv/bin/python scripts/self_check_latest_bookkeeping.py \
  --dashboard deliverables/dashboards/01_latest/ABS综合看板_20260924.html \
  --report /tmp/latest-bookkeeping-check.json
```

FAIL（非零退出，禁止替换上一有效面板/发布）：字段缺失、无效日期、来源或规则指纹不一致、项目/档位/明细对账错误、机构/金额歧义合并、孤儿规模、非法/负金额、布尔值/非法利率、关键公式无缓存、配售超过发行规模或已知档位金额、实际运行时列序/搜索/导出错误。判定规模差使用 0.0001 亿元容差；申购超额不适用配售上限。

WARN（保留原值，不虚构、不回退历史）：真实未披露申购、成本/规模缺失、配售不足、重复原始明细、同档不同成本、未知发行场所、辅助档位金额公式无缓存。辅助 R 金额未计算时不能确认档位上限，项目 J 规模上限仍为硬门禁；请用 Excel 重算保存以恢复完整档位核对。

如定稿已写入而后续面板刷新失败，台账会保留，旧面板不变，流程返回错误；修正后重跑同步。禁止宣称台账/面板已同步，发布门禁会拒绝这个状态。

项目概况新增“项目期限”，直接读取定稿台账 K 列“期限”，保留 `X+Y` 原格式（如 `21+3`、`0+47`），不相加改成总期限；缺失显示未披露。同项目期限冲突或面板期限与源表不符会 FAIL，期限公式无有效缓存会阻断更新。期限随每次台账更新同步，手机版复用同一字段。

### 最近3期查询（2026-10-11扩容）

每类资产在发行场所过滤、资产别名合并后，按自然日选最近3个不同簿记日期，而非简单截取3个项目；同日多个项目全部保留，不足3期展示全部可用期次。项目下拉显示“项目名称 · 簿记日期”，默认最新一期；同名跨期项目按日期分别保留，项目期限和明细随所选期次切换。门禁独立核对三期日期、全部项目及逐期明细，规则schema升级为v2。

2026-10-11，经用户确认以台账档位金额为准，将“2026东樾4号3期（东樾4-5）”（2026-09-01）的优先B机构配售同比例乘0.75、中间级同比例乘0.5，合计分别为0.3亿和0.2亿。仅修改总表六个V列单元格，不改申购明细、档位金额及其他字段；调整前台账已在04_archive备份。调整记录见 `03_test/东樾4-5_比例配售调整_20261011.json`。三期面板门禁已通过，共37项目、1380条明细；这次按用户明确指令处理，不代表以后可自动修正机构配售数据。

### 全量上线门禁

完整综合看板生成时签发独立的 `abs-ledger-provenance` 来源块，记录所有台账消费者使用的同一台账哈希与生产实现指纹。局部簿记刷新保留旧全量来源块、不重新签发；源台账或生产实现改变后，`--skip-generate` 同样拒绝发布，必须完整生成综合看板并传入消金、同业等其他模块源表，避免“新簿记 + 旧投资台账”的混合版本上线。手机版打包同时校验实际应用脚本，禁用入口或使用旧导航脚本会阻断。

项目规模 J、档位金额 R 的非空非法文本、NaN/Infinity、布尔值及负数均为 FAIL；真正缺失明确 WARN，不能将非法金额当作缺失关闭配售上限。辅助 R 公式无缓存仍按已明确的限制告警，不推算源值。
